# Phase 1 card dispatch — common rules (appended to every card packet)

Authority: `AUTH-OWNER-20260907-03` (record `…/scratchpad/packets/OWNER-DECISIONS-20260907-02.md`). Each card is its own TASK_PACKET (plan §15): the card file in `agent-tasks/` is the requirements; its §2 read set, §3 write set, §4 consumes/produces, §5 allowed communication, §6 invariants/transactions, §7 error obligations, §8 verification, §9 ceiling, §10 stop conditions, §12 reviewer scope, §13 expected evidence are binding. The Coordinator adds:

1. **Repo state**: the Phase 0 skeleton exists (see `evidence/handoffs/P0-skeleton-handoff.md` and root `README.md`): `uv` workspace, `server/app/main.py` (FastAPI factory), `server/app/db/` (engine, WAL, foreign keys), Alembic at `server/migrations/`, generated Pydantic models in `shared/rr_contracts/rr_contracts/generated/` (use them; never hand-write wire models), `tests/conftest.py` fixture loader (use it to feed `acceptance/fixtures/**` straight into tests), CI workflows. Card §3 paths are now the real layout (PROVISIONAL label lifted for the Python tree by OD-20260907-02).
2. **Write set = card §3 exactly**, plus the Alembic migration(s) your entities need under `server/migrations/versions/` (one revision per card, named after the card), plus `evidence/handoffs/<card>-handoff.md` and an evidence manifest `evidence/runs/<card>-E1-<UTC>.json` validating against `evidence/manifest.schema.json`. Nothing else. Shared files other cards also need (e.g. `server/app/main.py` router registration) are edited **only** by appending one clearly delimited include line; report it in the handoff.
3. **Contracts are read-only.** A defect in a contract, fixture or schema ⇒ `CR-<card>-nn` in the handoff with evidence; never edit the oracle to pass. Tests use fixtures as data: `given` rows are loaded, `events` are executed through the real service layer (not by calling the DB directly), `expected` rows/counts/hashes are asserted, `forbidden_effects` are asserted absent.
4. **Evidence discipline**: E1 = contract tests on fixtures; E2 = crash/fault injection tests the card names (SQLite failure injection via the wrapper in `server/app/db/`). Every test the card's §8 lists must exist and run; results with exit codes in the handoff; anything not run is NOT_RUN. Claim ceiling `IMPLEMENTATION_VERIFIED` for the card's scope only.
5. **Dependencies between Phase 1 cards** run in parallel: identity-merge is invoked by the ingest path — the ingest card calls `identity.resolve_target` / `identity.merge_works` through the `app.identity.service` interface the identity card provides; agree the function signatures from `contracts/ports.yaml` (operation id → `def <verb_noun>(...)` in `app/<domain>/service.py`), and if the other card's file is not there yet, code against the port and mark the integration test `xfail(reason="pending TC-…")` — do not stub the other domain inside your own package. Storage readiness's dependency on `TC-backup-restore-drill` is deferred: implement `recovery_required` handling per storage.yaml with the restore hook as an interface only.
6. **Capabilities**: network only for `uv`/`npm` installs; no secrets; no live X/Telegram/AI; no browser; no git mutation; `PYTHONDONTWRITEBYTECODE=1`; scratch under `…/scratchpad/<worker>/`.
7. **Quality bar**: `ruff` + `mypy --strict` clean on your package; no test skipped for a P0 scenario; no `TBD` in code comments; every error code raised is from `rr_contracts.generated` (never a string literal); every transaction boundary in card §6 is a single `BEGIN…COMMIT` in the service layer with the commit point named in a docstring.
8. **Handoff**: baseline §4 shape + card §13 evidence manifest; list every file with sha256; the exact test commands and their output summary; `CR-*` items; `lease_released_at`. Reply to the Coordinator ONLY: status, files created, tests run (counts pass/fail/xfail), evidence manifest path, CRs (≤25 lines).
